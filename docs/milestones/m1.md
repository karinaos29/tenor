# M1 · Hear

**Goal (architecture doc, Day 1):** mic capture, audio gateway, streaming speech-to-text, speaker labels, live transcript in the UI. **Demo: the transcript appears live**, on the replay call as well as on the live mic.

## What was built
```
backend/
  pipeline/events.py      Utterance + call events (call.start/stop, speakers.swap, call.started,
                          utterance.partial/final, speakers.updated, transcriber.status, call.ended),
                          bus-internal audio.level / transcript.*; REST ReplayList
  pipeline/bus.py         per-call async event bus, bounded queue per subscriber (pulled in from M2)
  audio/sources.py        AudioSource protocol: MicSource (browser frames), FileSource (WAV, real-time pacing)
  pipeline/transcriber.py Deepgram Nova-3 over a raw WebSocket: timeout, KeepAlive, 3 reconnects, fallback states
  pipeline/speakers.py    speaker labeler: first-turn rule, per-speaker loudness, smoothing, manual swap + lock
  pipeline/session.py     CallSession: source → level meter → transcriber → labeler → UI events
  app/main.py             WS /ws/call (one call per socket), GET /api/replays
  audio/replay.py         CLI: same CallSession, headless, prints transcript + latency summary
  fixtures/calls/         m1_hello.wav (36 s, two voices) + make_m1_clip.py + catalog.json
frontend/src/
  styles/tokens.css       dark Hiya-inspired theme + transcript voice tokens
  components/             StartScreen (hero, consent, MicCheck, ServiceList), LiveScreen (CallStrip,
                          Transcript, RightRail with empty states)
  lib/audio/              AudioWorklet capture → 16 kHz Int16 80 ms frames, level meter (pcm.ts unit-tested)
  lib/callSocket.ts, callState.ts, stores/call.ts   call protocol, pure state, relabeling
docs/architecture.md      imported from the .docx (+ diagrams in docs/img/), with a changes note
```

## What was measured
Real Deepgram, `uv run python -m audio.replay fixtures/calls/m1_hello.wav` (real time, 36 s call):

| Stage | n | median | p95 |
|---|---|---|---|
| `stt.connect` | 1 | 711 ms | — |
| `stt.partial_lag` (audio → interim words on screen) | 36 | **305 ms** | 718 ms |
| `stt.final_lag` (audio → final words) | 10 | 1082 ms | 2535 ms |
| `labeler` | 12 | < 1 ms | < 1 ms |

The partial lag meets the architecture target ("~300 ms to first words"). Final lag is dominated by endpointing (300 ms of silence) plus Deepgram's finalization. Speaker labels: 7 of 7 final lines correct in the browser replay after the M1 fixes. Before them, the caller's "Good" was split off as "You", and the opening "Hello?" would have flipped to "Caller" once loudness relabeled (see below).

Tests: backend **81 passed** (~3 s) + 1 opt-in live Deepgram test (`uv run pytest -m deepgram`, passed, 36 s). Frontend **37 passed**, typecheck clean, build OK. Browser: a replay ran end to end at 1280 px and 900 px. The UI also correctly showed "Lost connection to Tenor's server" when the dev server reloaded mid-call.

## What the real replay caught
- **Diarization split one voice into two speaker numbers** (0 and 2). Fixed: per-speaker loudness labels (`speakers.updated.user_indices` is a list).
- **The caller's first word went to the previous speaker** ("Good" | "afternoon…"). Fixed: a lone leading word glued to the next speaker with no pause is smoothed over.
- **Interim speaker numbers flip** before the final. Fixed: partial lines are neutral ("Speaking…") until final.
- **"Fast" replay lost most of the call** (the buffer dropped audio, and Deepgram live runs at about real-time speed). Fixed: files use backpressure, and the CLI plays in real time only.
- The test suite (written by a second model) found two more bugs: a corrupt WAV broke `/api/replays`, and post-swap classification assumed the user is the louder voice. Both fixed.

## What's left / known issues
- **Live mic on a real speakerphone call** hasn't been measured. The automated tests and the replay cover the same pipeline after the source, but the mic constraints (all processing off) need a real-room check.
- Mic frames are sent only after `call.started` arrives, so the first ~100 ms of a live call isn't transcribed.
- Misheard names ("Esther" for Eszter, "karmaker"): M2's extractor matches tickers and firm names against known lists.
- The latency log grows with partial-lag lines (~4 per second of speech). Fine for now; M4's eval screen may sample it.
- `uvicorn --reload` restarts on any file change in `backend/`, which drops an active call during development.

## Demo script (M1)
1. On the Start screen, press **Replay a test call**. The transcript fills in live: the caller on the cyan rule, "You" in bubbles on the right.
2. Press **Swap speakers**: every line flips, and "Labels set by you" appears. Press it again to undo.
3. Tick the consent box, **Check microphone**, **Start listening**, and talk with a phone on speaker. **End call** shows "Call ended · m:ss" and a "New call" button.
